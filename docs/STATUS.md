There is no remote. Everything is committed locally, and nothing is pushed or merged until the
owner says so. Each task has its own branch, and each branch is stacked on the one before it, because
later tasks build on earlier migrations. Review and merge them in order.

## Model suggestions

A model may suggest a label for a figure the reader could not label; a person confirms it (task 50b).

- **The switch:** per workspace, off by default, changed only by the owner (Settings, "Label suggestions"). With it off, no document text leaves the server and reconcile ignores stored suggestions.
- **The provider and region:** Anthropic's Claude API, processed in the United States. Only the figure, its stored context and the extractable field catalog are sent, never a deal or workspace name.
- **Environment:** `ANTHROPIC_API_KEY` (without it the worker makes no call), `AGIR_SUGGEST_MODEL` (default `claude-opus-5-5`), `AGIR_SUGGEST_EFFORT` (default `medium`). Installed SDK: `@anthropic-ai/sdk` 0.133.0.
- A suggestion is checked by `applySuggestions` and arrives as `needs_review` or a conflict, tagged "Suggested label, please confirm". Nothing is approved by itself.

## Known gaps

- **Foreign currency is detected only where a figure names it.** A bare "$" is read as the deal's currency
  (and Bergendal's figures carry no mark at all), including a "$" in an Excel format. A currency named in a
  table's column header ("Amount (USD)") or in a sheet title is not read; only the figure, its own label and
  the cell's number format are. Other currencies than CAD, USD and AUD are not recognised.
- **CI has not run on GitHub.** `.github/workflows/gate.yml`'s steps were replayed locally from a fresh clone
  (see Verified commands), but the workflow itself, the Chromium install on the runner and the trigger rules
  are unexercised until the repo is pushed.
- **French documents are read only where a label matches an alias.** Aliases and table headers are fixed
  word orders; a phrasing no alias lists is not mapped, and a figure the label's parenthesis qualifies
  ("Intérêts seulement (mezzanine)") is read from the label without the parenthesis, so it can fall to the
  senior field. French DSCR terms (RCD, CCD, RCSD) are not output phrases, because the minimum covenant uses
  them, as in English. A French LP share written as a share of equity is only read in the forms listed. A
  single space group is accepted only before a trailing "$"; "2 100 pi²" in a document with no other
  space-grouped figure is still refused. There is no vacancy field.

## Deviations from the plan

Where the code showed a better route than [the plan](plan-small-developers.md), the route taken and why.

- **One currency statement per report, not `CA$` on every figure** (step 1). Check messages and gate labels
  are inside the hashed, signed run result, so changing how they print money needs a new engine version
  and would change every stored run. Instead, each report's header line says "All amounts in Canadian
  dollars (CAD)", and the model export has a Currency row. English money formatting is the same in en-CA
  and en-US, so the formatter keeps its locale.
- **A deal created before migration `0004` has no currency**, rather than CAD. Giving old deals CAD would
  infer it from nothing. Their reports say "Currency not stated". New deals get CAD unless they say
  otherwise, and the currency cannot be changed after creation, so all of a deal's runs and reports agree.
- **"DCR" is shown at display time** (done in `task/08-plain-language`). Gate labels and check messages are part of
  the hashed result, so the stored text still says "DSCR"; the interface replaces the whole word with CMHC's
  "DCR", and in French "RCSD" with "CCD", the *coefficient de couverture de la dette* of CMHC's French multi-unit reference guide (Quebec brokers often say "RCD"). The glossary keeps the lenders' term ("called DSCR by many lenders").
- **The count of sponsor-stated inputs is derived, not stored** (step 2). It is counted from the run's stored
  input snapshot when an artifact is made, rather than kept as a new run column, because the snapshot already
  holds each input's status and a column would need a migration and could disagree with it. Whether that count
  caps the verdict remains a credit decision (under "Needs a person").
- **One migration per task** (`0004`, `0005`, and so on), not one `0004` for everything. Applied migrations
  are checksummed and the branches are stacked, so a shared file would change under a database that had
  already applied it.
