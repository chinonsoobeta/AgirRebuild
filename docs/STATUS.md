## Model suggestions

A model may suggest a label for a figure the reader could not label; a person confirms it (task 50b).

- **The switch:** per workspace, off by default, changed only by the owner (Settings, "Label suggestions"). With it off, no figure is sent for a label suggestion and reconcile ignores stored suggestions. This switch does not cover the AI reader (cards 160a and 160b): whenever `ANTHROPIC_API_KEY` is set, the worker sends the text of a deal's extracted documents to Claude (`AGIR_READER_MODEL`, default `claude-opus-5-5`) unless the workspace's owner turned "Read documents with AI" off (card C, `workspaces.ai_reading`). Without the key the rules alone read.
- **The provider and region:** Anthropic's Claude API, processed in the United States; both requests pin it with `inference_geo: "us"` (card C). Only the figure, its stored context and the extractable field catalog are sent, never a deal or workspace name.
- **Environment:** `ANTHROPIC_API_KEY` (without it the worker makes no call), `AGIR_SUGGEST_MODEL` (default `claude-opus-5-5`), `AGIR_SUGGEST_EFFORT` (default `medium`). Installed SDK: `@anthropic-ai/sdk` 0.133.0.
- A suggestion is checked by `applySuggestions` and arrives as `needs_review` or a conflict, tagged "Suggested label, please confirm". Nothing is approved by itself.

- An owner can set any value in the policy, for the workspace or for one deal; a deal value wins. Values looser
  than the lender's are allowed and flagged.
- Guards the owner accepted: every report names each change, who set it and when; the cited lender rules are
  always checked separately and shown on lender-facing reports ("Fails CMHC's …"); tolerance can only be made
  stricter and the source ranking is fixed; stress sizes are printed and a zero stress is flagged.
- Each value has an allowed range (in `THRESHOLDS`, `packages/contracts/src/policy.ts`); a stored value that no
  longer fits blocks the run with its name until it is changed or cleared.

## Known gaps

- **The first page loads 547 kB of JavaScript.** Since card I a screen's own strings load with its route group; the
  first visit downloads 547.43 kB (the libraries, 339.94 kB, and the shared app code, 207.49 kB). The largest parts of
  the shared code are the French translations of server messages (`FR_REASONS` in `apps/web/src/i18n.tsx`), the field
  catalog and its French labels from `@agir/contracts`, the shared components and the plain-words glossary
  (`strings/terms.ts`). An English visit does not need the French ones; loading them only in French would need an
  asynchronous language switch, which was not done.
- **The accessibility scan is automatic only.** axe-core finds about a third of WCAG problems; the scan does not open
  dialogs, menus, error states or the run while it is in progress, and no person has tested with a screen reader.
- **A bare "$" with no stated currency is read as the deal's.** A currency is read from the figure's own mark,
  its label, the cell's number format, the column header above it, the table or sheet name, a whole-table
  statement, or a number-free document statement (card 99). A figure with none of these, including a "$" in an
  Excel format (Bergendal's figures carry no mark at all), is the deal's currency. A statement that holds a
  number ("in 2025 US dollars") is not read. Other currencies than CAD, USD and AUD are not recognised.
- **CI runs on GitHub.** `.github/workflows/gate.yml` runs on every push of `main` (last checked 2026-10-25 with
  `gh run list`: the run for card 153b, `3ca9877`, succeeded). The `ui/*` branches are not pushed, so CI has not run on them.
- **The chain is one chain across every workspace.** Since card B, `GET /api/workspaces/:ws/audit/verify` answers
  members only, with their workspace's count (migration `0036`), but the walk still reads every workspace's rows, and the
  audit package's `audit_chain` check still uses `fn_verify_audit_chain()` with the installation's count
  (`apps/api/src/services.ts`). A per-workspace chain is ADR 0002 item S8.
- **The audit package cannot be checked on its own.** It holds the deal's events with `prev_hash` and `hash`
  (`apps/api/src/services.ts` line 647) but not the actor or the deal, which each hash covers, and the chain runs
  through every deal and workspace, so someone holding only the package cannot recompute it.
- **Sign-up is open unless `AGIR_SIGNUP=invite`.** The default (`open`) lets anyone create an account with a workspace of
  its own; a deployment for the pilot must set `invite` (card B). There is no way yet to invite a workspace member who
  has no account: under `invite`, only client invitations create accounts.
- **No mail provider.** Production uses `unsentMailer()`: verification, reset and change-of-address links are made but
  never delivered, and the screens say so (card B). A person who undoes an address change in production is left with
  no password and no reset link.
- **The standalone worker does not alert.** `apps/worker/src/main.ts` writes JSON lines in the same shape but has no
  `AGIR_ALERT_URL` hook; only the embedded worker's `job.dead` and `worker.error` are alerted.
- **Uploads are not scanned for malware.** The worker makes structural checks only (`apps/worker/src/index.ts` line 144).
- **Files are stored on the local disk by default**, under the data folder's `blobs/` (`fileStore` in
  `packages/db/src/storage.ts`); production logs a warning at start. `AGIR_BLOB_STORE=s3` uses an S3-compatible bucket
  (`s3Store`, card A), tested only against a fake client: no S3-compatible server was reachable here. Blobs are not
  encrypted in either store (ADR 0002 S1).
- **The deployment recipe is one host with Docker** (`deploy/`, `docs/deploy.md`, card A): no TLS, no mail provider,
  no worker jail or egress limits, and backups stay on the host unless someone copies them off. No hosting provider
  is chosen.
- **AI reading is on unless the owner turns it off.** Each workspace has "Read documents with AI" (card C, Settings);
  it is on for new and existing workspaces, as the owner made AI reading the default on 2026-10-24, and is not asked at
  sign-up as ADR 0002 §5 proposes. No redaction pass runs before the text leaves (ADR 0002 §5). Turning it on reads a
  deal only at its next extraction.
- **French documents are read only where a label matches an alias.** Aliases and table headers are fixed
  word orders; a phrasing no alias lists is not mapped, and a figure the label's parenthesis qualifies
  ("Intérêts seulement (mezzanine)") is read from the label without the parenthesis, so it can fall to the
  senior field. French DSCR terms (RCD, CCD, RCSD) are not output phrases, because the minimum covenant uses
  them, as in English. A French LP share written as a share of equity is only read in the forms listed. A
  single space group is accepted only before a trailing "$"; "2 100 pi²" in a document with no other
  space-grouped figure is still refused. There is no vacancy field.

- **Closing and deleting is row deletion, not crypto-shredding** (`card/F-close-account`). A purged workspace's rows
  and unshared files go, but backups keep them, and the audit trail keeps its events (with their payloads) for good.
  The files are deleted after the database commits; a file whose bytes are uploaded again into another workspace in
  the moment between the purge and the delete would lose its file. Jobs already queued for a closed workspace
  (reading a document, rendering a report) still run until it is purged. With `AGIR_RETENTION_DAYS` unset, a closed
  workspace is kept for good.

## Deviations from the plan

Where the code showed a better route than [the plan](plan-small-developers.md), the route taken and why.

- **One currency statement per report, not `CA$` on every figure** (step 1). Check messages and gate labels
  are inside the hashed, signed run result, so changing how they print money needs a new engine version
  and would change every stored run. Instead, each report's header line says "All amounts in Canadian
  dollars (CAD)", and the model export has a Currency row. English money formatting is the same in en-CA
  and en-US, so the formatter keeps its locale.
- **A deal created before migration `0004` has no currency**, rather than CAD. Giving old deals CAD would
  infer it from nothing. Their reports say "Currency not stated". New deals get CAD unless they say
  otherwise, and the currency cannot be changed after creation, so all of a deal's runs and reports agree.
- **"DCR" is shown at display time** (done in `task/08-plain-language`). Gate labels and check messages are part of
  the hashed result, so the stored text still says "DSCR"; the interface replaces the whole word with CMHC's
  "DCR", and in French "RCSD" with "CCD", the *coefficient de couverture de la dette* of CMHC's French multi-unit reference guide (Quebec brokers often say "RCD"). The glossary keeps the lenders' term ("called DSCR by many lenders").
- **The count of sponsor-stated inputs is derived, not stored** (step 2). It is counted from the run's stored
  input snapshot when an artifact is made, rather than kept as a new run column, because the snapshot already
  holds each input's status and a column would need a migration and could disagree with it. Whether that count
  caps the verdict remains a credit decision (under "Needs a person").
- **One migration per task** (`0004`, `0005`, and so on), not one `0004` for everything. Applied migrations
  are checksummed and the branches are stacked, so a shared file would change under a database that had
  already applied it.

## Fallback gate and held-out measurement (card 154)

- Command: `npm run gate -- --tier=fallback`. It runs only the `fallback: no model` tests (`apps/api/test/api.test.ts`) with `ANTHROPIC_API_KEY` removed from the child environment; the `release` tier runs the same step. The test uploads an invented document set with no key and no injected provider, checks that no request reaches `fetch` or the Anthropic SDK, that the documents are extracted and reconciled, that a run is produced as before card 160a, and that no `ai_readings` (or `label_suggestions`) row is written.
- The rule reader is the fallback for the AI reader (card 160a) and must keep working with no key.
- At each phase end Claude runs the held-out measurement outside the repository: `measure-part.sh <part> <previous>` (in `agir-reading-work/harness/realdocs/`), run from the repository root; it sets `SETS=v2,v3,v4,v4c,v5,v6,v7,v8,v9,v10,ref` itself and measures the checkout named by `AGIR_ROOT` (default `~/agir-v2`; set it to measure another worktree). It scores the bank, the real documents, the readings and the actions; bank and scores are diffed against the phase baseline (`bank-before.json`, `score-before.json`), readings, real documents and actions against `<previous>`. Claude also byte-compares the four outputs against the previous part with `cmp`. Everything is written in the harness's own folder. Blind and real documents, the harness and its outputs are never stored in the repository.
